调用关系：

~~~text
main.py
  ├─ validate_config()：先查配置
  ├─ validate_input()：再查学生信息
  └─ calculate_total()
       ├─ score_academic() → education + ranking
       ├─ score_english() → english
       ├─ score_competition() → competition
       └─ score_research() → research
~~~

评分函数不读取文件、不打印、不修改传入的数据。只有 main.py 负责文件和终端。

## 2. 学生输入：照这个填写

~~~json
{
  "name": "演示学生",
  "school_name": "示例211大学",
  "undergraduate_major": "计算机科学与技术",
  "target_major": "计算机科学与技术",
  "ranking": {"position": 10, "total": 100},
  "english": [
    {"type": "CET6", "score": 560}
  ],
  "competitions": [
    {"event": "示例算法竞赛", "year": 2025, "level": "国家级", "prize": "三等奖"}
  ],
  "research": [
    {
      "id": "paper-001",
      "title": "示例机器学习论文",
      "type": "期刊论文",
      "status": "已发表",
      "role": "第一作者",
      "field": "机器学习"
    }
  ]
}
~~~

| 字段 | 含义与要求 |
|---|---|
| name | 姓名，选填，不参与计分 |
| school_name | 必填；具体学校名称或已配置别名，不能只写“211” |
| undergraduate_major | 必填；本科专业标准名称或已配置别名 |
| target_major | 选填；拟申请专业。不提供时采用本科专业；提供时不能留空 |
| ranking.position | 个人名次，正整数 |
| ranking.total | 同一排名统计范围的专业总人数，正整数且不小于名次 |
| english | 必填数组；无成绩填 []；每项包含考试类型与总分 |
| competitions | 必填数组；无竞赛填 [] |
| research | 必填数组；无科研填 [] |

排名比例 = position / total，10/100 就是前 10%。请保持名次与总人数统计范围、统计时间一致；并列名次使用学校提供的官方名次。

字符串自动去除首尾空格；名称按已配置名称或别名精确匹配。不认识的字段会报错，避免拼写错误被静默忽略。JSON 不支持注释。

## 3. 评分规则

### 3.1 院校背景，最高 20 分

背景分 = 学校基础分 + 该校本科专业实力分。

| 学校档次 | A | B | C | D | E |
|---|---:|---:|---:|---:|---:|
| 学校基础分 | 15 | 13 | 11 | 9 | 7 |

| 专业档次 | 强 | 较强 | 普通 |
|---|---:|---:|---:|
| 专业实力分 | 5 | 3 | 1 |

985、211、双一流、普通一本放在学校的 tags 中，可以重叠，但标签本身不另外加分。
学校的 level 是团队维护的评分档次。相同标签可以对应不同档次；不同学校的同名专业也可以属于不同专业档次。

### 3.2 专业排名，最高 40 分

根据学校档次和本科专业档次选曲线，例如 B:较强。
所有 15 种组合都已配置，曲线覆盖 0%～100%。0% 是插值用的边界节点，学生名次仍必须从 1 开始。

| 曲线示例 | 前 5% | 前 10% | 前 20% | 前 30% |
|---|---:|---:|---:|---:|
| A:强 | 40 | 39 | 37 | 34 |
| B:较强 | 39 | 37 | 34 | 30 |
| D:普通 | 37 | 34 | 29 | 24 |

节点之间线性插值。例如 B:较强，前 10% 得 37 分、前 20% 得 34 分，那么前 15% 得 35.5 分。

公式：左端分数 + (当前比例 - 左端比例) / (右端比例 - 左端比例) × (右端分数 - 左端分数)。

示例：A 档强专业前 30%，背景与排名合计 54 分；D 档普通专业前 10%，合计 44 分。
这表达了学校、专业与排名的联动，并不表示所有真实院校都符合这个差值。两项同时受到学校影响是当前模型的明确设计，后续需要用实际案例校准，避免学校权重过重。

### 3.3 英语，最高 20 分

成绩落在两个阈值之间时取较低阈值对应的分数，不插值。低于首个非零阈值计 0 分。多个成绩取最高得分；同分时展示输入顺序中最先出现的成绩。

| 考试类型 | 成绩阈值 → 得分 |
|---|---|
| CET4 | 425→8，500→10，550→12，600→13，650→14 |
| CET6 | 425→12，500→15，550→17，600→19，650→20 |
| IELTS | 5→8，5.5→11，6→14，6.5→17，7→19，7.5→20 |
| TOEFL | 60→8，70→11，80→14，90→17，100→19，110→20 |

CET4/CET6 输入 0～710 整数；IELTS 输入 0～9、步长 0.5 的总分；**TOEFL 本版本只接受 0～120 分制总分**，其他计分尺度不要直接代入。页面应把量尺写清楚。

这些是本系统自定义分档，不是官方考试等值表。本版本未核验考试日期、成绩有效期、单项成绩和院校英语门槛。

### 3.4 竞赛，最高 10 分

| 级别 | 一等奖 | 二等奖 | 三等奖 |
|---|---:|---:|---:|
| 国家级 | 10 | 8 | 6 |
| 省级 | 5 | 3 | 2 |
| 校级 | 1.5 | 1 | 0.5 |

同一 event + year 只取最高分，不重复计算省赛和国赛。同名赛事不同年度可以累计。
赛事名称需由前端统一填写；不要把“某赛事省赛”和“某赛事国赛”当成两个 event，否则系统无法自动识别它们属于同一赛事。不同赛道若要独立计分，应使用明确、统一的赛事赛道名称。

去重后累加，最多 10 分。当前没有赛事认可名单、学科相关性或团队角色折扣；奖项均假定已被业务认可。

### 3.5 科研，最高 10 分

每项得分 = 基础分 × 成果状态系数 × 个人贡献系数 × 专业匹配系数。

| type | 基础分 | status 可选值与系数 | role 可选值与系数 |
|---|---:|---|---|
| 期刊论文 | 6 | 已发表 1；已录用 0.8；投稿中 0 | 第一作者 1；共同第一作者 0.8；其他作者 0.4 |
| 会议论文 | 5 | 已发表 1；已录用 0.8；投稿中 0 | 第一作者 1；共同第一作者 0.8；其他作者 0.4 |
| 发明专利 | 4 | 已授权 1；申请中 0 | 第一发明人 1；其他发明人 0.4 |
| 科研项目 | 3 | 已结题 1；进行中 0.6 | 负责人 1；参与者 0.5 |
| 软件著作权 | 2 | 已登记 1；申请中 0 | 主要完成人 1；其他完成人 0.4 |

专业匹配优先对照 target_major，没有时对照 undergraduate_major：

- direct：研究方向直接对应目标专业，系数 1。
- related：方向对应的专业出现在目标专业的 related 列表中，系数 0.7。
- unrelated：专业和方向均已配置，但无直接或相关映射，系数 0.2。
- 未知专业或方向：待确认，不直接按 unrelated 计分。

field 填研究方向，不填自由描述的论文摘要。已有方向包括机器学习、软件系统、信号处理、统计建模、机械设计、经济研究、文学研究，可在配置中扩展。
related 是从目标专业出发的显式关系；如需双向相关，请在两个专业中分别配置。

同一成果 id 的完全相同记录只计一次；同 id 内容不同则报错。id 必须稳定，不能通过给同一成果换 id 来重复计分。当前按不同成果记录累计，没有自动识别论文、专利、项目之间的同源关系，也没有按期刊级别或会议档次进一步分级。

## 4. 修改哪里

| 要修改的内容 | 文件 |
|---|---|
| 新增学校、院校标签、学校档次、该校专业档次 | config/school_major_levels.json |
| 改分值、排名曲线、英语阈值、科研系数 | config/scoring_rules.json |
| 增加专业、专业别名、相关专业、研究方向 | config/major_relations.json |
| 改院校排名计算方法 | score_academic.py |
| 改英语/竞赛/科研计算方法 | 对应的 score_*.py |
| 改最终返回结构 | calculate_total.py |
| 改命令行和文件读写 | main.py |
| 加输入约束或配置检查 | validate_input.py |

添加真实学校时，在 schools 数组中增加如下结构，把占位名称改为真实名称，档次由团队确认：

~~~json
{
  "name": "在这里填写真实学校名称",
  "aliases": ["在这里填写学校常用简称"],
  "tags": ["211", "双一流"],
  "level": "B",
  "majors": {
    "计算机科学与技术": "较强",
    "软件工程": "强"
  }
}
~~~

新专业先加到 major_relations.json 的 majors 对象，再在学校中引用。每次修改规则或数据，请更新对应 version；三个文件的版本都会写入输出。真实数据录入后同步更新学校配置的 notice，说明数据来源、维护口径和适用范围。

脚本会检查曲线是否完整、分数是否越界、专业引用是否存在、名称别名是否重复等，避免配置错误继续计分。
